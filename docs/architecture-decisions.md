# 研究系统的架构约定

本文保留历史 Skills 交接中仍适用的设计理由，并按当前代码校正。独立 React 前端见 [星图工作台](../frontend/README.md)，真实模式已接入 `research_agent_full`，原有模拟数据和动画演示独立保留。

## 图入口与评估边界

[langgraph.json](../langgraph.json) 注册四个入口：

| 图 ID | 用途 | 导出对象 |
|---|---|---|
| `scope_research` | 澄清需求、生成研究简报 | `research_agent_scope.py:scope_research` |
| `research_agent_skills` | 单个研究员：加载方法论、搜索、反思、压缩 | `research_agent_skills.py:researcher_agent_skills` |
| `research_agent_supervisor` | 多研究员调度 | `multi_agent_supervisor.py:supervisor_agent` |
| `research_agent_full` | Scope → Supervisor → 最终报告 | `research_agent_full.py:agent` |

当前单体研究实现为 Skills 版。各层的评估边界不同：research-agent 评估读取单个研究员的 `compressed_research`；supervisor 评估检查单步委托；完整图输出 `final_report`。单体评估分数不能直接解释为完整报告质量。

研究员节点主要使用同步模型与工具调用；supervisor 通过异步调用组织多个研究员。直接调用完整图时使用 `ainvoke`，不要把早期文档的“全程同步”理解为整个项目的执行模型。

## 工作台的研究与执行边界

计划 2 将配置绑定到一轮逻辑研究。服务端目录由现有六角色模型定义去重构成，客户端只选择不可变修订 ID。配置选择属于原提交 payload，公开执行快照与受理意图在同一 SQLite 事务中提交，之后写入检查点；同一 turn 重试不会再解析当前默认配置，同轮澄清继承先前快照。

`run_configuration.py` 保留模型定义及 Skills 正文修订的服务端归档。凭据仅保留环境变量引用，端点不返回浏览器。恢复使用原修订重建模型，兼容性 / 归属 / 输入摘要仍需验证；不能将模型配置隔离理解为任意节点恢复或多实例协调。

每个父节点建立 ContextVar 作用域，异步子图继承，网页摘要线程池显式复制。按角色与修订缓存独立模型和绑定包装，不在执行期间改环境或全局模型。默认独立图仍兼容原对象，三类 agent 调用继续共享限流器。Skills 索引和正文共同受允许集合约束，且自动模式也保存正文修订；实际成功加载由事件单独展示。

一条真实工作台会话对应一个 LangGraph thread。一轮研究可以包含首问和多次澄清回答，因此可以对应多个 LangGraph run。澄清仍使用 `goto=END` 返回问题，后续回答以同 thread 的新输入启动；没有迁移为 `interrupt/resume` 协议。

完整图新增 `prepare_research` 和明确的业务状态。进入新批次时用 `Overwrite` 重置带 reducer 的 `notes`、`raw_notes`、`supervisor_messages`，并清除旧简报、报告、来源、错误和轮次；新的 scoping 上下文仅保留本次问题。只有同批次的澄清续问保留消息历史。旧研究保存在工作台历史中，不参与下一轮研究提示词。

`research_status` 区分运行、等待补充、成功、失败、部分完成。报告必须有 `report_research_id` 归属，前端还核对当前 turn，以排除尚未重置的旧检查点。执行异常可以由节点转换为安全的业务失败，所以 API run 的成功不能直接映射为 UI 研究成功。来源从真实工具消息中提取，区分搜索命中与对用户明确指定页面的直接 HTTP 读取；后者标记 `retrieval: specified_url`。LLM 自己生成的链接不会冒充来源。

前端使用版本 1 的显式接口契约。旧提交先落盘标识，再创建原生 run；未知结果按 metadata 回读，不自动重发。1B 的新提交额外使用可选受理契约，由服务端在 SQLite 中先确定 run ID，再创建原生执行；相同内容和标识始终对应同一受理。标准 HTTP API 仍没有客户端指定 run ID 的契约，幂等保证来自新的服务端受理层。

主图阶段、实际简报和报告继续从检查点读取；研究员数量与任务细节由原生 `custom` 事件流驱动。每次实际委派有独立任务标识和协调轮次，覆盖并行与后续追加任务。真实模式模型来自后端模型工厂的实际构造快照，Skills 由研究员自动加载；模拟菜单的值不传给后端。接口细节见 [后端接口约定](../frontend/docs/backend-contract.md)。

## 研究员进度与最终结果分开处理

计划 3 为报告增加独立事件类型、写作尝试和日志命名空间，不复用研究员事件的含义。`report_streaming.py` 显式管理中途断流后的有限重新生成，每次更换 writing attempt；SDK 连接重试与生成重试分别计数。正文只来自最终模型文本，并在有界窗口合并后先提交 SQLite、再发布 custom SSE。

客户端将草稿与持久回放位置一并保存，按完整归属、事件 UUID、连续序号和 UTF-8 字节 offset 归并；缺口后的文本不直接接到已有段落。旧失败尝试和替换前日志独立保留，新生成替换活动草稿。最终报告增加 run / turn / 受理 attempt / writing attempt 归属，仍必须由终态检查点确认。写作恢复只新增写作 run，原检索事件的归属与历史模型快照不改变。

父图的研究节点要等整个协调子流程返回后才写检查点，因此单靠主图轮询无法展示中途检索。`research_events.py` 在一次父节点调用内建立记录器，用 ContextVar 将记录器与任务身份传给并行协程及同步工具线程，同时发布原生 SSE 并保留安全事件。独立研究员图及评估输出保持原约定，提示词和模型配置没有加入遥测对象。

研究员完成、工具返回、SSE 结束和完整研究成功是不同层次的状态。客户端只用事件更新任务节点与检查器，最终业务结果仍依据 run、`research_status` 和报告归属。失败事件保留成功兄弟任务；没有确认终态的节点不显示成功。

事件正文只含任务、查询 / Skills 名称、阶段、时间、来源和压缩笔记；排除模型推理、原始工具正文与异常响应。记录器给并发事件分配统一顺序，每个事件有独立 UUID；客户端校验研究 / 提交 / run 归属并去重，演示状态与真实事件继续隔离。

子流程返回时把事件列表写入父检查点，新研究清空该列表。父节点完成前的持久化由下面的事件日志承担；原生缓冲与浏览器缓存继续用于实时显示和去重。

## 事件日志与执行恢复分开

锁文件对应 LangGraph 1.1.3、API 0.8.7、inmem runtime 0.28.1、CLI 0.4.26。已核对运行时实现：SSE `message_stores` 是内存列表，原生 `PersistentDict` 另有约 10 秒的刷盘周期。父研究节点返回前的事件无法仅靠 `durability=sync` 或保存 `Last-Event-ID` 保证跨进程回放，因此保留原生 SSE，并增加最小的 SQLite 安全事件日志及只读分页接口。

`event_journal.py` 按 thread / run 保存归属、事件 UUID、递增序号、日志 UUID 和关闭 / 缺口标记。先提交日志，再发布事件；WAL 与 FULL 同步保护已提交事务，同进程建库串行化，事件追加使用 SQLite 事务。失败不会中止研究，界面据缺口标记保留已知成果并说明不完整。保留期和存储路径属于后端配置，不暴露给浏览器。

本地进程身份用于识别旧捕获过程，新的子流程调用也隔离任务 ID。旧任务没有完成或失败证据时不会继续显示为执行中；原生 run 和检查点仍是业务状态来源。`sealed` 仅说明事件捕获结束。强制停止测试已验证：研究工具执行中、父检查点尚无事件时，重启能够回放已提交事件，而原生 run 可能仍标为 `running`、并未实际续跑。

浏览器按后端地址、thread、research、turn、run 保存 SSE 游标和独立的业务恢复序号。事件与恢复位置原子写入同一份本地会话，写入失败保留内存内容但不推进位置；检查点回读与事件合并互不覆盖。退避重连和分页回放只观察已有运行，演示继续隔离。旧后端和旧缓存通过可选能力、默认值及单独丢弃无效位置保持兼容。

这项选择仅面向单进程本地开发，不将 SQLite / 进程身份当作多实例协调或共享部署协议。1B 在下述独立受理层增加受限执行恢复；按次模型 / Skills 与正文流式已完成，完整真实验收的剩余边界见前端验收记录。

## 幂等受理与执行恢复

`submission_journal.py` 为提交保留不可变内容摘要、前一 turn、固定原生 run UUID 和恢复尝试；SQLite 意图先于原生创建提交，因此“run 已创建但应答未返回”不会遗失提交身份。`submission_api.py` 使用服务端互斥、持久意图及前一 turn 检查拒绝并发与过时输入。内存锁只负责本地排斥，不独自承担崩溃后的幂等性。

同一 turn 的恢复有独立 attempt 和新 run；重试同一恢复请求沿用 attempt。模型 / 工具调用前，完整图节点先核对受理记录，持久化当前进程归属、节点与输入摘要。旧进程已开始的尝试不能在重启后直接再次执行原输入。只有尚未进入节点的意图可完成原受理；已经开始的执行必须走检查点验证。

`atlas_runtime.py` 集中依赖锁定版本的内部 `create_valid_run(run_id=...)`、原生锁和持久化对象。同步写入使用互斥与独立临时文件，检查点 blobs / writes 先于索引落盘，并 fsync 后替换文件；原生定期刷盘也使用同一写入器。没有编辑 site-packages，仍使用原生 worker、run 列表、状态和 SSE。多文件存储不被当作通用事务，恢复还必须核对读取结果；不支持的运行时不声明 1B 能力。

当前恢复白名单是 `clarify_with_user`、`write_research_brief`、`final_report_generation`。服务端要求旧执行进程已经退出，检查 research / turn / run、唯一下一节点、阶段、进入节点时记录的输入摘要、模型标识及有效笔记；然后以精确 checkpoint 与 `input: null` 继续。澄清 / 简报 / 写作模型可能再次调用，现有内部重试保持不变。报告恢复不会再次进入已完成的检索和压缩。

研究员仍封装在 `supervisor_subgraph` 中；父检查点没有细分到中断的单个工具，不能仅凭事件推断可从该工具之后执行。因此中途退出保留已确认笔记、来源与报告，提供明确的新建研究入口。事件晚于中断回执补回时也立即保留有效成果，缺少终态证据的任务不伪装成完成。

确认终态之前持久化检查点，并在受理库中固定其位置。已完成 turn 的重复请求不会启动新 run，后续 turn 也不会覆盖它的回读结果。前端将提交、恢复尝试、当前执行和事件来源分别保存；写作恢复沿用原检索 run 的事件位置。刷新、重连和聚焦仍只观察；执行重试 / 恢复由明确操作触发，且新标识必须先成功写入浏览器存储。

当前保证要求同一套本地受理库、原生检查点、事件库与配置归档被保留；受理身份不按事件的保留期清理。配置隔离已完成，跨设备发现、任意研究节点恢复及多实例部署另行设计。原生故障验收与实际调用计数见 [验收记录](../frontend/docs/verification.md)。

## Skills 按需加载

2026-10-15 增加独立于模型委派的全局要求：原始用户要求和简报传入各研究员，子任务范围仍单独保留。明确点名的 Skill 由运行时在模型 / 检索前真实调用 `load_skill`；其余 Skill 继续按需选择。当前配置禁止或不存在的必需 Skill 明确失败。精确 URL 列表在证据消费前执行，原始命中与采用来源分别审计；细节与验证见 [Kimi 约束修复](../frontend/docs/kimi-fixes-2026-10-15.md)。

[skills_loader.py](../src/deep_research/skills_loader.py) 在模块导入时扫描包内 `skills/*.md`，形成元数据和正文快照。系统提示词只包含名称与描述索引，模型通过 `load_skill` 获取所需正文，减少无关方法论占用上下文。

每份 skill 的 frontmatter 至少包含 `name`、`description`，且 `name` 必须等于文件名主干。格式有误的文件会记录 warning 并跳过；整个目录缺失则报错。未知 skill 名会返回错误说明及可选名称，便于模型重新选择。

Skills 位于 Python 包内，并通过 `pyproject.toml` 的 package-data 随包安装。增加新文件时检查打包结果和索引；修改磁盘文件后需要重启进程才能刷新导入时的快照。

## 研究证据与方法论分开处理

[research_agent_skills.py](../src/deep_research/research_agent_skills.py) 构造 `raw_notes` 时保留 AI 消息和 `RESEARCH_TOOL_WHITELIST` 中工具的消息。目前工具白名单只有 `tavily_search`，`load_skill` 与 `think_tool` 的工具正文不进入这些原始笔记。

新增检索工具时，需要同时检查白名单及 `_has_real_search_results()` 的判断；仅把工具挂到模型上还不够。2026-10-16 起，压缩模型只读取检索工具正文、子任务和全局要求，不再读取模型自述、思考工具或方法论正文；`raw_notes` 的追溯格式保持不变。

实际采用的来源正文另存于 `source_evidence`，每份最多 24000 字符，按精确 URL 和完整消费正文哈希绑定，保留正文／片段类型、来源方式与截断位置。研究员、主管和主图独立传递该字段，新研究清空；写作最多接收 48000 字符原文。全部采用来源都完整落入预算时直接依据原文写作，避免沿用派生笔记的失真和冗长结构；否则保留笔记及明确的不完整标记。该字段参与恢复输入摘要，旧检查点缺字段时维持旧摘要格式。

有来源正文的新研究还使用现有 FINAL_REPORT 角色核验候选稿，最多两次核验、一次语义修订；传输重试与语义修订共用三次写作生成预算。草稿由各自写作尝试日志保留，`report_reviews` 记录对应正文哈希、写作身份、核验结论和程序测得的汉字数，并参与恢复摘要。只有通过核验的最终稿写入终态报告；核验不可用或一次修订后仍失败则部分完成。旧检查点没有来源正文时保持原写作路径，空核验列表不表示语义通过。来源传递本身不证明覆盖完整，模型核验也不能代替逐项验收；边界和实测见 [P0 进展](../frontend/docs/p0-fact-fidelity-progress-2026-10-16.md)。

核验复用共享结构化 helper 的 JSON/schema 提示构造；OpenAI 兼容客户端显式请求 JSON 对象，不使用强制工具调用，也不追加格式修复模型调用。schema 严格校验且检查响应结束原因；截断、非法类型、额外字段或矛盾结论均不能通过。格式错误只保存可见响应哈希、长度、允许的结束原因和校验错误类型，不保存响应正文、校验输入或推理内容。原有 Qwen `/no_think` 与空 `choices` 回退路径不变。

2026-10-17 增加通过结论的来源定位要求。核验读取与写作相同预算内的正文及行号，为全部编号断言选择来源与行范围；程序从实际正文提取片段，核对覆盖、来源编号、有效范围和非空白内容。通过记录在 `source_support` 中保存断言哈希、消费正文哈希及字符位置，仍绑定原写作尝试和报告哈希。长报告将相邻断言合并至最多 80 项，不丢弃尾部；标题和引用编号保留。没有原文的旧检查点沿用旧路径，已经完成的报告不会被重新核验或改写。

核验前另有一次不读取候选稿的来源条件选择，避免只检查已有句子而遗漏整条前提。选择先独立提取最多三项实质适用／安全／适配前提，再选择最多五项操作、兼容或指标条件；没有实质前提时必须明确说明限定来源的证据边界。声明、标签、构建成功和性能测试不能替代实质前提，短比较报告也不因此扩写为实现教程。通过结论的 `condition_coverage` 必须引用报告断言覆盖每项条件，或明确说明某项确实不适用。

每个写作节点的瞬时 `ReportReviewContext` 缓存来源条件，绑定实际证据和原始要求，不进入检查点；两稿复用同一选择。来源选择、至多两次候选稿核验及它们的传输重试共用四次模型读取预算，预算在读取前扣减。正常路径增加一次来源选择，但不增加原有最大读取预算；与三次生成上限及实验 SDK 最多五次 HTTP 尝试合计，写作节点仍最多 35 次 HTTP 尝试。`report_reviews` 保存条件类别、原文位置、断言覆盖和已用读取次数，整体继续参与恢复摘要。

修订同时接收程序测得的汉字数、目标范围和独立来源条件。条件旁的 `source_excerpt` 从同一写作预算内的原文按已验证位置和哈希提取，供核验与修订直接比较限定，避免再次压缩条件摘要；片段只加入模型输入，不重复写进检查点。英文、数字、标点和代码名不计入汉字数。修订意见中的实现示例用于解释问题，不自动成为短报告必须新增的内容。

原文位置只证明出处及覆盖，不证明语义蕴含，也不能保证模型选全重要前提。错误位置、不完整覆盖、矛盾的空前提声明或不可用核验均不能通过；原有严格 JSON 校验、安全诊断和失败保留策略继续适用。真实 `y` 轮曾在机械和模型核验通过时遗漏实质安全审查，不能据此关闭 P0。最新实测、实验调用参数和独立内容审查见 [P0 续验](../frontend/docs/p0-fact-fidelity-results-2026-10-17.md)。

无搜索结果或压缩结果为空时，会返回明确的研究未完成标记。这是对下游界面和调度的失败信号。压缩模型与最终报告模型已有有限重试，早期交接中的“待增加压缩重试”已不适用。

## 提示词的约束

- 研究 brief 保留用户明确表达的需求；当前日期只提供背景，不应自动变成用户未提出的筛选条件。
- 枚举与多实体比较先覆盖所有类别或实体，再深入局部，避免反复研究少数对象。
- 用户没有限定来源时，官方页面无法提供具体数据可以寻找可信第三方来源；显式范围优先于这种默认回退、Skill 查询模板与默认来源数量。无合规证据须如实说明。
- 报告中的具体事实使用编号引用，并在 Sources 段映射到来源。质量评估同时检查覆盖与引用，不能只看报告长度。

提示词调整的历史证据与局限见 [评估记录](evaluation-history.md)，运行与兼容性约定见 [维护说明](maintenance.md)。
