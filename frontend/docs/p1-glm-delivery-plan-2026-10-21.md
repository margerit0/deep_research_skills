## 第一阶段：入口及一次完整验收

批次 `.local/p1-glm-delivery-20261021`；替身入口 `p1-glm-delivery-20261021-mock01`（2160/5320），真实入口 `p1-glm-delivery-20261021-native01`（2161/5321），各用独立源码快照、状态目录和四个数据库。仅新入口可执行一次，旧启动器不执行。

先使遥测安装幂等并用稳定共享模块持有状态。真实网络前验证 graph/http 两次导入得到同一 runtime、同一包装及正确请求归属；本地原生 API 替身必须经过两轮提交、JSON 摘要/简报、压缩、写作和核验以及刷新。替身不加载真实 `.env`，通过 mock transport 彻底阻止模型和搜索外网，结果单独标记，不能代替真实验收。对读到 stop / `[DONE]` 后消费者主动关闭的 GeneratorExit 单独分类，原始字段保留，结束前异常仍属不可用。

入口离线检查与本地原生替身门槛通过后，冻结实际源码、启动器、原两轮用户输入、模型变量、预算与新身份。模型为 `z-ai/glm-5.3`，原 base URL/key，六角色流式，Scoping 和网页摘要选择共享 helper 的 JSON 对象策略。来源选择、写作、候选核验提示和 schema 固定，不注入实验选择提示。写作 high/32000、核验 high/128000 与旧隔离参数相同；不重跑旧简报样本。

真实完整业务样本恰为 1；观察 7200 秒，服务硬上限 7500 秒，首轮澄清观察 1200 秒。保留三次生成、四次选择/核验读取、一次语义修订；SDK 最多五次 HTTP，退避 3/6/12/24 秒。模型总 HTTP 上限 120，搜索 HTTP 上限 20，图循环边界不变。401/403、冻结哈希变化、路由不可用、预算耗尽则停止；不可用保留分母，不补跑至成功。低 TPS 由事先明确的观察时间容纳，流内服务端错误与本地错误独立分类。

逐请求记录 HTTP 状态、流内错误、finish_reason、`[DONE]`、读取/schema 结果、首字和完整耗时；不保存模型推理。完整验收同时要求业务 succeeded/complete、400–650 汉字、精确两页来源、每任务 Skill 先于真实搜索、逐句来源支持及重要适用/安全前提、核验和报告归属/哈希一致、刷新不新增执行且正文一致。原生 run success 和 HTTP 200 不替代这些要求。上游 completion=0 异常保留，实际 token/费用未知。
