每次使用新数据库、thread、research、turn、run 和写作身份；最多观察 1800 秒，专用后端保护期限 1950 秒。SDK 每次读取至多五次 HTTP 尝试，原来的 3／6／12／24 秒退避与 Retry-After 规则不变。每个写作节点最多三次生成、四次来源选择／核验读取，最多一次语义修订。其余角色、搜索和共享 RPM 沿用已验收 harness。

模型同步、异步和共享结构化回退客户端均显式 `proxy=None`、`trust_env=False` 并校验 TLS；搜索独立使用原配置。启动前验证原输入与默认成功实录中的两轮文本一致；核对源码、前端实际数据／配置、harness 与环境哈希。每次启动入口拒绝复用已启动身份，结束只清理本轮子进程。

同时保留原生业务完成率和独立内容通过率。内容要求沿用 400–650 汉字、两条精确来源、全部关键前提／例外／操作证据缺口，以及真实 Skill 预加载。HTTP 200、图 run `success`、原文定位或模型 `passed` 均不能替代完整验收。草稿与最终报告分别核对，不用离线改写替换原生结果。

原生运行的检索结果、生成稿和提示日期仍可能变化；记录实际来源／输入哈希并说明分组，不宣称整条链的所有输入完全相同。首批三次只提供初步重复性证据。

## 遥测

新采集器在计数前通过七项离线检查，覆盖 SSE 分片、用量重复事件、缺失结束标记、`length`、非流式用量、传输异常与异步字节透传。各轮一致增加 `stream_usage=True`，请求网关返回实际用量尾块；这一点相对 P0 有变化，因此 P0 不纳入当前三次分母。

- 单独记录响应头等待、首个可见输出、正文消费结束或关闭时间，以及连接异常、正文断流、HTTP 状态和结束原因。
- 安装的 SDK 在收到 `[DONE]` 后关闭流，未必消费传输 EOF。此时使用请求开始至正常关闭的耗时，包含网络和解析；不能把 `bodyEof=false` 单独判为断流，也不能把该时间当成纯模型计算时间。
- 流式用量取最后一次服务端累计值，重复用量事件不相加。非流式响应沿用既有解码后的 usage 记录；底层压缩字节的解析失败不等于 API 格式错误。
- 只报告有真实 usage 的请求；缺失值、失败尝试用量及费用不估算。只保存推理字段是否出现和 token 计数，不保存推理正文。

## 单变量离线对照

三次原生基线结束后，最多取每次运行的首个**实际进入候选稿核验**的草稿，共最多三对。没有候选稿核验输入的运行单独列为不适用，不以旧成功稿补齐。每对完全固定草稿、原始要求、来源正文、来源条件和生产核验提示；先校验重建的提示与原生请求消息哈希一致，再运行 high／low，两者 token 上限同为 128000，其他请求字段一致。按案例交替 high-first 和 low-first。

该对照只比较候选稿核验。来源条件固定使用相应原生 high 选择结果，因此不能据此比较条件选择能力。每个 arm 最多 1800 秒，沿用每次读取五次 SDK HTTP 尝试和一次正文断流重读；不新增检索、写作、原生执行或离线修订。独立内容判断先于配对调用保存，以审查误放行、错误拒绝和有效问题，不能仅比较两种模型输出是否相同。

P2 同步汇总网关可靠性；出现明确外部阻断时保存现场并停止后续批次，不无界重跑。P3 的成功实录默认接入已经完成；其他导出或报告体验不在本次实验中扩张实施。实验结果用于提出日常配置建议，不自动改写生产默认。
