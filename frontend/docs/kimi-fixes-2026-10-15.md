## 约束如何到达实际执行

[research_requirements.py](../../src/deep_research/research_requirements.py) 将用户原始要求、整体简报与模型生成的子任务分开传递。研究员保留自己的任务范围，不共享其他研究员的对话。用户明确要求的 Skill 在首次检索前通过真实 `load_skill` 调用加载；方法论正文受本轮归档配置与允许集合控制。禁用、未知或不允许的要求返回明确错误，不能静默跳过或伪造成功事件。

精确页面约束从用户明确的 URL 列表中解析，例如“资料范围固定为……”“仅使用……”或 `Use only ...`。普通参考链接、官方优先和 `site:` 查询不自动变成页面白名单；其他自然语言要求仍按原文传递。本轮实现不宣称能把任意自然语言限制全部转换成机器规则。

来源在进入网页摘要前检查。URL 比较保留路径、版本和查询参数，只归一化主机大小写、默认端口和片段。原始搜索命中逐条保留在 `source_audit` 中，越界页面不进入摘要、压缩笔记或最终来源。当搜索不能定位用户明确给出的页面时，工具直接读取允许 URL；重定向每一步仍须在范围内，且不会沿页面链接或模型自行补出的地址扩展。

直接读取的来源带 `retrieval: specified_url`，与搜索服务命中分别记录。HTTP 200 之外还须取得可用正文；无合规证据时不调用压缩模型生成空壳报告。最终报告链接也必须来自实际采用的来源。新要求字段参与恢复输入摘要；旧检查点缺少这些字段时维持原有摘要格式。

## 保留事实限定

网页摘要、压缩和最终报告共用证据限定要求：保留条件、例外、版本、测试范围和工作负载，区分实测、历史目标与建议；支持声明或重新编译不代表完成线程安全适配；来源未说明的参数语义不能补写。风险的充分条件不能改写为“仅在此时有风险”，一种回退路径也不排除其他失败原因。用户指定的来源、查询方式和短报告篇幅优先于 Skill 模板、第三方回退及默认详尽偏好。

短报告优先保留实质安全审查、工作负载例外和目标的时间属性，删减未要求的 API 写法和重复检测命令。这一最终取舍提示在第四轮全流程完成后补强，通过新的独立 Kimi 写作身份验证；没有重跑已完成的 thread 或替换原生检查点。独立修订同时提供已读的两篇来源原文和明确的审查反馈，因此不能把改善单独归因于提示词，也不等于整条摘要链已自动通过逐事实验收。

网页摘要通过结构化流式读取取得最终值；中断的部分摘要不当作完整结果。摘要失败时保留最多 24000 字符的实际来源原文，超出部分明确标注为未覆盖，修复原先只保留前 1000 字符导致尾部限定丢失的问题。异常沿用安全诊断，共享结构化 fallback、Qwen `/no_think` 与其 payload 诊断路径保持不变。

较长的主管、研究员与压缩调用，对 `ChatOpenAI` 使用流式传输，并由 LangChain 在节点内汇总为完整消息。通过 `invoke` / `ainvoke` 传递 `stream=True`，保留压缩模型原有的整次调用重试边界；不会直接对 `RunnableRetry` 调用 `stream()` 绕过重试。其他提供商与独立调用对象保持其原有方式。真实 HTTP 替身测试验证了同步 / 异步工具参数分片解析，以及重试时该选项仍生效。

## 在线写作回读提示的原因

新诊断复现了一条确定的错误路径：研究 SSE 的游标也会创建空的 `reportStreams` 条目。旧判断只检查数组是否非空，因此研究还没进入写作就开始回读写作日志；多次 `missing` 被显示为重试，并累积退避时间。第一轮新实测在没有任何报告正文的研究阶段捕获了 34 次这种等待。

现在只有实际写作事件或 `writing` / `complete` 阶段才触发写作日志回读，研究阶段会清除无用的旧重试状态。界面分别表示尚未就绪、暂时失败和真实缺口；恢复后清除提示，保留已接收草稿，读取与刷新均不创建 run。

`atlas:report-replay` 诊断事件仅包含时间、研究 / run / 写作身份、阶段、HTTP 状态、游标及错误类别，不包含报告正文、完整响应、网关地址、凭据或模型推理。错误类别区分 HTTP、网络、超时、JSON、schema、归属、序号 / 游标和本地保存失败。

这证明了一条可重复的代码原因。2026-10-14 原首段截图没有相应请求诊断，不能据此将当时每次提示都断言为同一个原因。

## 模型、提示词与思考等级

明确发现的问题首先涉及上下文传递、来源消费、摘要降级与提示词冲突。提高思考等级不能保证弥补丢失的要求，也不能替代实际来源边界。连续 504 另属实际请求链路问题，不能直接解释为报告内容质量差。

本轮请求没有显式设置 `reasoning_effort`、`thinking` 或 `enable_thinking`，但第四轮澄清 / 简报响应的网关计数已包含 53、76、311 个 `reasoning_tokens`。因此“没有显式设置”等于“思考关闭”的判断不成立。工作流的 `think_tool` 是研究步骤，与供应商原生思考等级不是同一设置。未做思考等级或不同模型的受控对比，当前证据不能量化提高等级的收益；没有依据将开启高等级列为完成研究的必要条件。
