### 本轮发现并修复的问题

首次后端回归发现并发首次建库时 `PRAGMA journal_mode=WAL` 偶发锁竞争，导致其中一条研究只发送事件而未记录。已串行化同进程初始化，并在新的数据库上重复并发验证；后续事件仍使用 SQLite 事务。正常回读不再重复执行建表和迁移。

运行中长期没有日志此前可能一直静默重试，结束的日志也可能缺少任务终态；现已分别展示暂时无法回读或记录不完整。日志重启后的旧任务不会因原生 API 仍报 `running` 就继续显示执行动画。

核对锁定的 LangGraph 1.1.3、API 0.8.7、inmem runtime 0.28.1、CLI 0.4.26 后确认：原生 SSE 缓冲只在内存，运行元数据有独立刷盘边界；CLI 还会覆盖持久化环境变量，其配置校验会过滤顶层 `disable_persistence`。旧替身配置仅在 `env` 内设置 true，不能证明关闭持久化。现用 `tests/atlas_fixture_server.py` 在专属目录调用同版本原生服务入口，提前加载环境并显式关闭持久化；原生 API 测试在发送前核对这些条件。

Windows 上通过 npm 自动启动 Vite 的旧验收方式曾卡在测试进程清理。本轮普通原生验收显式管理专用 Vite，取得完整退出结果；恢复验收还等待旧端口释放，并核对进程身份变化。最终测试服务均确认退出。

## 真实后端接入第一轮 · 2026-10-10

### 已验证的实现

- 一条工作台真实会话对应一个 LangGraph thread；每轮研究有独立 research ID，每次澄清回答有 turn ID 和服务端 run ID。
- 澄清通过同 thread 的新 run 继续。图入口清空上一轮简报、报告、累积笔记、协调消息、来源和轮次，新的问题不会混入旧报告。
- 等待补充、运行中、成功、失败、部分完成分别展示。无有效笔记时不调用报告模型；部分研究失败或写作失败时保留有效成果，绝不以模拟报告兜底。
- 刷新先回读服务端，按 research / turn / run 归属匹配。网络响应丢失只查询已有运行，不自动重发；存储写入失败时阻止真实提交。
- 真实模式显示后端六个角色的实际模型，Skills 固定自动。每次提交前重新读取模型配置；已完成研究的配置快照保持不变。演示菜单不影响真实执行。
- 原有全流程演示继续在独立内存会话中运行。真实研究在后台完成时，退出演示可看到真实结果，演示不会建立额外后端 run。
