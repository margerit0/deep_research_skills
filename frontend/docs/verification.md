## 真实后端接入第一轮 · 2026-10-10

基准提交 `7c5ff9c`，分支 `chore/public-edits`；开始时工作区干净，与交接一致。本轮保留原视觉与演示，实现 `research_agent_full` 的接口、状态定义、澄清续问、简报、研究、报告、来源和刷新回读。真实模型完整成功仍有下述网络限制，不能将替身结果记为真实研究成功。

### 已验证的实现

- 一条工作台真实会话对应一个 LangGraph thread；每轮研究有独立 research ID，每次澄清回答有 turn ID 和服务端 run ID。
- 澄清通过同 thread 的新 run 继续。图入口清空上一轮简报、报告、累积笔记、协调消息、来源和轮次，新的问题不会混入旧报告。
- 等待补充、运行中、成功、失败、部分完成分别展示。无有效笔记时不调用报告模型；部分研究失败或写作失败时保留有效成果，绝不以模拟报告兜底。
- 刷新先回读服务端，按 research / turn / run 归属匹配。网络响应丢失只查询已有运行，不自动重发；存储写入失败时阻止真实提交。
- 真实模式显示后端六个角色的实际模型，Skills 固定自动。每次提交前重新读取模型配置；已完成研究的配置快照保持不变。演示菜单不影响真实执行。
- 原有全流程演示继续在独立内存会话中运行。真实研究在后台完成时，退出演示可看到真实结果，演示不会建立额外后端 run。

### 真实服务联调：尚未通过完整研究

真实服务已启动，前端确实调用了生产配置的 LangGraph API，配置接口和运行 / 检查点回读可用。按用户指定，将本地后端六个模型角色配置为 `z-ai/glm-5.3`，使用指定的新网关和密钥；后端以 `NO_PROXY=*` 直连，密钥与本地网络配置不入库。

实际遇到并保留的证据：

- 先前网关返回 `503 control_unavailable`（`Commercial admission is unavailable`）。更换网关后，经代理的请求返回 403 HTML 拦截页。
- 按要求改为直连后，一个最小 Chat Completions 请求成功，但正式澄清请求仍发生连接超时 / 连接失败，不能据此认定完整调用链已通。
- 同配置的独立澄清诊断最终得到 `APIConnectionError → ConnectError → CERTIFICATE_VERIFY_FAILED: self-signed certificate`；沙箱外复测仍失败。系统和 Python certifi 证书库都未能通过对该域名的证书校验。
- 真实失败 run 结束后，UI 正确显示“研究失败”，`final_report` 为空，没有把 API run 的正常返回标记成研究成功。该轮研究 thread 为 `152e3589-2aaf-48a0-b630-7c0ef5f8140d`，run 为 `01a125f3-9040-79f2-b011-38dc240c15f9`，仅供当前本地服务回读核对。

因此，本轮**没有验证真实模型完成澄清续问、Tavily 检索和最终报告交付**。需要先恢复当前机器到网关的可靠直连及有效证书链，再使用 `ATLAS_LIVE=1` 重跑验收；测试和接口实现已保留。没有关闭 TLS 校验，也没有将替身内容标为真实结论。
