## 当前实现与调用方式

来源正文传递、严格两页范围、实际 Skill 预加载、程序字数检查、原生核验与一次修订沿用前次实现，详见 [原实现与历史结果](p0-fact-fidelity-results-2026-10-16.md)。本次补充的通用提示覆盖数字比较基线、括号内结论、配置改变的实际影响、操作取值／生效／运行中切换的证据缺口，以及保留 API 的构建、版本与适用前提。短比较报告只在用户明确要求时纳入初始化函数、平台构建步骤或未来版本计划。

这些规则用于一般来源核对，没有注入 Python 场景答案清单，也没有将独立审查意见或改写稿提交回原生运行。核验仍返回 `passed` 和 `issues`；有来源正文时，模型要想通过还必须在 `support` 中为每个编号断言选择 `source_id` 与起止行号。程序只展示与写作相同预算内的实际原文，拒绝缺失／重复断言、不存在的来源、倒置／越界或全空白行范围，直接从原文提取摘录。通过记录保留断言哈希、原文哈希与字符起止位置，不依赖模型抄写引文，也不保留私有推理。拒绝无需提交完整的支持清单。一次语义修订、三次生成上限和原有 HTTP 尝试上界保持不变。

断言按句末标点划分，标题与引用编号一并保留，长报告合并相邻片段至最多 80 项而不丢弃尾部。原文锚定只证明摘录来源和核对覆盖，不证明语义蕴含，仍需独立逐句审查。

来源条件选择不读取候选稿，只读取原始要求和实际来源。最新 schema 单独要求最多三项实质适用／安全／适配前提，再选择最多五项其他决策条件；无实质前提时必须明确说明证据边界。声明、标签、构建成功或性能测试不能替代实质适配，短报告也不必复述实现教程。通过时 `condition_coverage` 引用报告断言覆盖全部条件；确实不适用的条件允许说明原因，缺失重要前提不能用“不适用”代替。

每个写作节点的 `ReportReviewContext` 缓存选择并绑定来源和要求，不进入检查点；两稿复用条件。来源选择、两稿核验及传输重试共用最多四次模型读取，在读取前扣减。一次修订、三次生成上限不变；本实验 SDK 最多五次 HTTP 尝试，写作节点仍是 `(3 + 4) × 5 = 35` 次 HTTP 尝试上界。条件类别、原文位置、覆盖和读取次数保存在已参与恢复摘要的 `report_reviews` 中。

修订会收到程序实测的原稿汉字数、目标范围和独立来源条件。条件旁的 `source_excerpt` 由程序从同一写作预算内按位置和哈希提取；条件概括若不完整，以实际原文为准。片段只加入核验／修订输入，不重复写入检查点。英文、数字、标点和代码名不计入汉字数；风险句保留“可能”时仍须保留来源限定的对象、使用规模或其他触发条件。

字数已在 400–650 范围内的原稿优先保留正确句子和结构，只补核验指出的实质缺口，并给出到约 500 字目标的净变化量。条件及原文是核对依据，不是新增事实清单；不会通过扩写所有实现示例来满足审查。原稿本来超出篇幅范围时才要求重新安排全文。仍只有一次修订，不增加生成或核验预算。

用户本次明确要求后续模型调用不走代理。新的隔离入口 [prepare_direct.py](../../.local/p0-fidelity-20261017/prepare_direct.py) 为同步、异步及共享结构化回退的模型客户端显式设置 `proxy=None`、`trust_env=False`、TLS 校验开启；六角色继续使用 `deepseek-v4.1-flash` 和原网关／凭据。实际 socket 记录核对原网关的 443 端口。搜索继续使用既有配置。生产 `.env`、原有配置归档字段和共享 Qwen `/no_think` 回退未修改。
