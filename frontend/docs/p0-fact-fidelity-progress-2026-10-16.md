## 本次实现

- 新增 [source_evidence.py](../../src/deep_research/source_evidence.py)：在范围过滤后的真实检索处理处捕获正文／片段，记录精确 URL、来源方式、完整消费正文 SHA-256、字符数和片段起止位置。同一 URL 的不同正文版本分别保留；不从模型或 Skill 提取证据。
- 每份来源保留最多 24000 字符；写作证据正文合计最多 48000 字符。截断、搜索片段和缺失正文均显式标记。它是有界原文传递，不是自动事实提取，也不保证长来源尾部已经覆盖。
- 来源证据独立于压缩文本，经研究员、主管和主图传递。并发调用使用独立 ContextVar，摘要线程池继承上下文；按 URL 与正文哈希去重，新研究清空。
- 压缩模型只接收检索工具正文、子任务及全局要求，不再接收模型自述、`think_tool` 或 Skill 正文。`raw_notes` 仍保留原约定供追溯，不能将它当作纯来源证据。
- 写作系统消息明确用户篇幅、比较维度和取舍优先级；实际来源正文附于写作输入，笔记与原文冲突时以原文为准。不新增模型角色、语义修订或写作尝试，原有重试上限不变。
- `source_evidence` 纳入 `submission_journal.state_digest`；旧检查点缺字段时仍使用原摘要形式，并在写作输入标明缺少正文。新增证据不加入公开研究事件，不改变前端事件协议。

上述确定性检查只证明来源绑定、边界、字段传递和恢复行为。是否正确选择事实、保留关键限定以及满足短报告语义要求，仍需真实模型验收。
