# 计划 3：真实报告正文流式显示（待实施）

规划日期：2026-10-13。计划 3 尚未实施；2026-10-14 收尾的 GLM / Kimi 离线实录只展示已保存内容，不是在线报告正文流式。1A、1B、计划 2 的状态、配置、视觉和独立演示继续作为基线。供应商复测结果与进入条件见 [交接入口](next-steps.md) 和 [最新验收](verification.md)。

## 实施顺序与验收门槛

1. **先确定写作事件及尝试身份。** 为报告增加可选能力和独立事件类型，不改变研究员 v1 事件的含义。范围至少包括后端、thread、research、turn、run、受理 / 恢复 attempt 和独立 `writing_attempt_id`。同一 run 内每次真正重新生成正文都要新建写作尝试；连接重试、观察重连与重新写作分别计数。开始、正文增量、失败、模型输出结束分别记录事件 ID 和单调序号；输出结束不等于检查点已确认。
2. **接入实际最终写作调用。** 只从 `final_report_generation` 取得正文增量，不暴露推理字段、工具参数、其他节点输出或原始供应商载荷。当前调用是 `selected_model(..., retry=True).ainvoke(...)`，默认写作模型已有最多三次的重试包装；实施前核对锁定版本的流式及重试行为，不能只把 `ainvoke` 改名为 `astream` 并假设中途断流会正确重试。保持六角色快照、共享限流及有限重试预算，避免 SDK 与应用重试无意叠加。
3. **持久化与回放先于界面拼接。** 复用 1A 的先提交再发布原则，为写作记录明确的日志命名空间、尝试边界与回放位置。正文按短时间 / 大小窗口合并成有界块，避免每 token 一次 SQLite 事务。存储缺口、日志丢失、后端退出和旧尝试终态缺失须显式表示；只靠内存 SSE 无法承诺刷新 / 重启可恢复草稿。写作恢复沿用原研究配置和研究来源事件，新增写作 run / 尝试，不重跑检索。
4. **前端按尝试归并，终态以检查点为准。** 在现有报告位置显示“正在生成”的实际草稿，沿用 Markdown 和现有布局。每个尝试按事件 ID / 序号去重，只应用连续增量；遇到缺口先回放，不直接接上较晚文本。新写作尝试替换活动草稿，失败尝试保留明确身份，不能把两次生成拼成一篇。保存草稿与恢复位置须原子完成；切换会话、刷新、演示进出不串内容。匹配归属的终态检查点用完整 `final_report` 校准正文和状态，不能仅凭流结束显示成功。
5. **先完成确定性故障验收，再补真实交付。** 使用独立测试目录、端口和明确标记的流式替身，检查服务端 run、模型尝试和检索计数。只有实际供应商生成的首段在写作完成前可见、最终正文与所属检查点一致、真实来源和引用核验通过，才能记录为真实流式验收通过。

## 必须覆盖的情形

| 情形                           | 验收结果                                                               |
| ------------------------------ | ---------------------------------------------------------------------- |
| 正常写作                       | 首段在模型完成前可见；最终全文逐字等于所属检查点报告                   |
| 同 run 内写作失败后重试        | 新 `writing_attempt_id`；旧草稿不与新正文拼接；计数符合有限预算        |
| 断线、重连、重复和乱序增量     | 同一观察作用域不重复拼接；缺口补齐后再推进；没有额外执行 POST          |
| 刷新、后端重启、日志缺失       | 已持久化草稿可核验；缺失明确提示；恢复观察不新建 run                   |
| 1B 写作恢复                    | 新 run / 写作尝试，原配置不变；检索与压缩次数不增加，最终报告归属正确  |
| 空正文、写作失败、部分研究成功 | 保留有效笔记 / 来源；草稿不是成功报告；业务状态符合现有契约            |
| 并发研究、后续提交、演示切换   | 草稿、最终正文、游标和尝试均隔离；演示不请求真实模型                   |
| 内容与展示安全                 | 不显示推理或其他节点内容；Markdown 半成品、长文及 320–1440 px 布局可用 |
| 旧服务与旧缓存                 | 能力缺失时继续以检查点显示完整报告；旧研究员事件与历史可回读           |
