## 实现和确定性边界

- `source_evidence` 在来源范围过滤后记录实际消费正文／片段的精确 URL、来源方式、完整正文 SHA-256、字符数和片段位置。每份最多 24000 字符，写作正文合计最多 48000 字符；截断、片段与缺失正文明确标记。同一 URL 的不同正文哈希分别保留。
- 研究员、主管和主图独立传递证据；并发上下文隔离，新研究清空。压缩模型只读检索正文、子任务和全局要求，不再读取模型自述或 Skill 方法论。`raw_notes` 原追溯格式保留。
- 全部采用来源完整落入写作预算时直接依据原文写作，避免沿用失真的派生笔记；否则保留笔记与不完整标记。明确约数字数的短报告使用简洁模板，排除旧长报告模板的取舍冲突；优先保留关键条件，删减未要求的函数／宏名清单和历史展望。
- 明确的“约 N 字”从原始输入解析，程序按来源章节之前的 `[\u4e00-\u9fff]` 计数。约数范围为 0.8N–1.3N，本场景始终 **400–650 汉字**；450–550 是写作目标，不替换验收范围。
- 原生核验复用 FINAL_REPORT 角色，最多两轮核验、一次语义修订。非法 JSON、核验不可用或修订仍不合格不得通过；旧检查点缺来源正文时兼容旧路径，空核验列表不表示语义通过。
- 核验复用共享 helper 的 JSON/schema 提示构造，并显式请求 JSON 对象；严格校验而不自动修补含糊 JSON，不增加格式修复调用。SDK 提前报告长度截断也保存安全诊断：可见响应 SHA-256、字符数、结束原因及错误类型，不保存推理或原始响应。核验只要求已有断言和用户指定维度所需的实质条件，不把未要求的 API 示例、平台细节单独列为遗漏。
- 原稿、修订和断流重试各有 writing attempt，全部正文保留在日志。传输重试与语义修订共用三次生成预算；`finished` 仍只是生成结束。终态仅绑定通过稿，`report_reviews` 保存对应哈希、写作身份、核验结论和程序字数。
- `source_evidence`、`report_reviews` 纳入恢复摘要，新研究重置，缺字段旧检查点保持原摘要形状。完成后的重复提交不会重写。
- 主管和核验的缓冲流读取对三类读取异常最多额外重试一次，不重试 HTTP 403 等拒绝。半截工具参数不会派发。按本次 SDK 最多五次 HTTP 尝试，写作节点最多三次生成加四次核验读取，合计 **35 次 HTTP 尝试上界**；其他角色及搜索原有重试另计。

来源记录不保证长文完整覆盖，模型核验仍可能误报或漏报，因此真实通过仍需逐句来源审查。未增加模型服务、数据库或前端事件类型，未替换实录。具体代码见 [来源证据](../../src/deep_research/source_evidence.py)、[核验](../../src/deep_research/report_review.py)、[写作与尝试](../../src/deep_research/report_streaming.py)。
