## 唯一变量与独立标准

只改变 `select_source_conditions` 的 system prompt：先判断某项来源条件是否影响原始问题的决定，再区分实质适用／安全／适配前提与其他决策条件；用忠实概括表达短报告所需的审查层级。支持声明属于兼容行为，不能挤占实质前提；具体 API、分配步骤或平台操作不能自动成为短比较的独立义务。保留来源中的对象、触发条件、例外、建议强度及用户所问操作的证据边界。

schema、来源正文、用户要求、候选稿、写作与候选稿核验提示、模型和调用参数均保持一致。评价标准先于模型请求保存；不把标准或案例答案注入生产提示。

离线共五例，每例旧／新提示各一次，共十个 arm，两个不同案例可并行。前三例取历史 P0 合格稿、P1 high02 不合格稿及上轮 native02 合格首稿，是已见回归；后两例为新建的合成插件／数据迁移资料，各有合格短稿与缺失安全前提的不合格稿。合成材料是本批设计样本，不宣称留出集泛化能力。每个 arm 先真实选择来源条件，再用原核验器检查冻结候选稿，同 arm 复用选择结果。

独立检查必要前提是否遗漏、声明是否错分类、实现细节是否过度要求、语义强度／触发条件是否失真、来源锚点是否正确，并分别记录正例误拒、反例误放行和有效拒绝理由。无法取得有效选择或核验决定时计为不可用；不追加样本或改标签。选择质量和下游决定分开报告，重复调用不是独立样本。

## 调用与原生上限

沿用 DeepSeek `deepseek-v4.1-flash`、原网关和凭据，模型显式直连且校验 TLS；搜索沿用原独立配置。来源选择／核验 enabled/high、128000，写作 enabled/high、32000，温度和其余角色配置不变。每 arm 1800 秒、最多四次模型读取；每次读取 SDK 最多五次 HTTP 尝试，传输重读和既定退避不变。实际 usage 取最后累计值，缺失保持未知，不估算费用。

离线完成并独立审查后，最多两次原生完整流程，串行、新身份、新数据库和新端口：`p1-selection-20261020-native01` 用 2121／5281，`native02` 用 2122／5282。沿用原两轮用户输入、1800 秒观察／1950 秒后端保护、最多三次写作生成／四次选择与核验读取／一次语义修订。失败计入两次分母，不补跑。401／403、冻结文件变化或原生搜索路径不可用时停止剩余计划。

原生分别评价业务终态、400–650 汉字、逐句来源支持和重要条件、修订是否必要及是否引入缺陷，以及来源／Skill／报告身份／字节偏移／刷新零新增执行等机械要求。离线通过不能替代原生交付。实验后仅在证据支持时保留新提示；否则撤下该单变量，保留完整失败记录。生产 `.env`、模型配置归档、默认成功实录和历史证据保持原状，未授权提交或推送。
