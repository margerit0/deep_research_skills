## 用户目标和已确认的方向

用户计划用 React 前端替代 LangGraph Studio 的前端，同时保留清晰的 agent graph，能看到研究包含哪些步骤、当前执行位置和各研究员的进度。

最初提供了「星图工作台」「研究手记」「协作指挥台」三种方向。用户选择继续改进「星图工作台」，并提出两轮明确反馈：

1. 界面需要类似 Codex app 的对话工作区，输入框里可以选择模型，另有独立的 Skills 下拉框。
2. 对话版布局获得了“这一版好多了”的反馈，但模型和 Skills 控件太像大号表单字段，要求参考 Codex app 下拉框的大小和样式。

随后用户要求添加 Apple 风格的 Glassmorphism 半透明效果，并增加点击 graph 节点查看详细信息的检查器。本轮已实现这两项，保留对话布局、可收起流程图和紧凑菜单；用户尚未将其确认为最终定稿。

2026-10-10 的续稿在此基础上进一步加入液体玻璃效果，并优化 UI 布局。侧栏与运行图谱改为有外侧留白的独立悬浮面板，正文保持开放布局；收起图谱后，对话及输入框居中且限制最大阅读宽度。使用分层渐变、半透明填充、背景模糊、饱和度、明暗边缘与阴影模拟玻璃厚度，没有给文字应用扭曲或模糊。输入框、侧栏和检查器的边缘高光可跟随鼠标，触屏及减少动态效果时关闭跟随。保留已有节点检查器与本地演示交互，没有引入应用依赖。

最新反馈要求“优化一下配色，并且将模型和 skills 的下拉框改成之前的样式”。当前已将蓝紫青环境光收敛为珍珠白、银灰和少量灰蓝强调，深色对应石墨灰。两个选择器参照 `atlas-pickers-model-open.png` / `atlas-pickers-skills-open.png` 恢复实色菜单、11 px 圆角、细边框和轻阴影，移除菜单自身的玻璃模糊、渐变与指针高光。后续不要再自动把菜单改成透明玻璃样式。

随后用户提供截图，指出当前收起状态只剩文字，缺少模型箭头、Skills 的层叠图标及箭头。仅恢复展开菜单样式没有解决该问题；原先本地包装内嵌 Lucide 的验证也没有覆盖宿主图标缺失。现已为两个选择器中的 8 种 Lucide 图标嵌入本地生成的 PNG 遮罩，保留原本的 `data-lucide` 占位符；库不可用时占位符自身显示同款图标，宿主替换为 SVG 后不会重复。无需网络请求或等待脚本初始化。遮罩取自已安装的 Lucide 1.8.0，生成记录与 ISC 许可在 `vendor/` 中。不要删除此兼容显示，也不要用自带完整图标库的预览作为唯一验证依据。

## 当前界面

- 左侧：最近对话、新研究入口。
- 中间：用户消息、研究回复、研究简报、进度摘要；底部是消息输入框。
- 输入框底部：并排的模型和 Skills 选择器，发送按钮在右侧。
- 右侧：可收起的流程图；点击 7 个节点中的任意一个，下方检查器会同步更新。收起流程图后，聊天区域自动展开。
- 检查器：可切换「概览」「输入 / 输出」「执行记录」。概览包含节点职责、当前状态、演示运行模型、耗时、来源或任务数量及当前步骤；输入输出包含节点标识与任务内容；执行记录按时间列出工具活动和结果。研究员内部循环保留在详情里，不增加全局主节点。
- 检查器可以独立收起，点击节点或「节点检查器」按钮重新展开；切换节点保留当前页签。左右方向键、Home/End 可切换页签，Esc 收起并把焦点交还所选节点。
- 配色与玻璃材质：最新候选为 Apple 银白、Claude 暖陶、青绿 · 林间；侧栏、图谱、节点、输入框和检查器保留半透明填充、背景模糊、高光边缘及悬浮阴影。顶栏融入背景，模型和 Skills 菜单使用各色板的独立实色底。
- 深浅色跟随当前外观，窄屏时重新排布内容。
- 使用系统字体；图标沿用宿主 Lucide。没有增加 React、后端调用或新的应用依赖。设计控件包含外观、流程图宽度、节点圆角、「玻璃模糊」与「边缘光感」。默认图谱 350 px、节点圆角 14 px、模糊 28 px、边缘光感 65%。旧会话保存的设计参数仍可恢复。

最新选择器的样式基准：

- 桌面端约 28 px 高，内容决定宽度；系统字体下默认两个按钮各约 81–82 px。
- 单行名称、小箭头、透明底色，悬停或展开时出现轻微底色。
- 展开为约 232 px 宽、11 px 圆角的实色菜单，向上弹出；选项行约 32 px 高，右侧对勾表示当前选择。菜单不使用模糊、玻璃高光或透明背景。
- Skills 菜单保留图标及“自动选择”分隔线。
- 窄屏会向内调整菜单位置；长名称可截断并提供完整标签。
- 不要改回“标题在上、选中值在下”的两行大号选择框。

演示运行开始时保存 `runModel` / `runSkill`。修改输入框的选择不会改写当前运行节点显示的模型；新一轮演示才记录新选择。待执行节点不显示已完成输出或历史活动；演示推进后，研究员的工具、输出和记录同步切换到完成状态。读取上一版保存的新研究会话时，可从已有消息恢复其演示运行配置。

后端模型由 `src/deep_research/model_config.py` 按角色和环境变量构建，部分模型在模块导入时实例化；真实的按次模型切换还没有实现。现有 Skills 由 `skills_loader.py` 建立索引，研究员通过 `load_skill` 按需加载；界面手动选择也尚未传入真实运行。不要在继续改稿时顺便修改后端或把凭据放进前端。

## 流程图必须尊重项目结构

完整研究图的主节点：

1. `clarify_with_user`：需求澄清。
2. `write_research_brief`：研究简报。
3. `supervisor_subgraph`：研究协调与并行研究。
4. `final_report_generation`：最终报告。

研究员内部是 `llm_call → tool_node → llm_call` 的循环，随后进入 `compress_research`。方法论加载、检索与反思是内部活动，不应被误画成新的全局主节点。研究员返回结果后，协调器可能继续委派任务；并行研究不是保证一次就完成的线性进度条。

项目维护约定以根目录 `AGENTS.md`、`docs/maintenance.md` 和 `docs/architecture-decisions.md` 为准。

## 继续改稿时保留的交互

- 两个选择器是独立的按钮与菜单，菜单项使用 `menuitemradio` 和 `aria-checked`，不是原来的原生大号 select。
- 点击或键盘可选择；方向键移动，Esc 关闭并返回触发按钮，点击外部关闭；同一时间只展开一个菜单。
- 用户输入支持 Enter 发送、Shift + Enter 换行，并避免打断输入法组词。
- 预览沙箱不允许原生表单提交：保持发送按钮 `type='button'`，由本地 `submitMessage()` 处理。不要改为 `form.requestSubmit()`。
- 模型和 Skills 的选择应稳定保留，不能被异步旧状态覆盖。现有 `clientId` / `revision` 用来忽略本次渲染自己的旧状态回写，不要随意删除。
- `window.openai.widgetState` 及 `setWidgetState` 只用于保存预览交互状态，不能把它们理解成后端研究 API。
