# v8 · 报告片段同步新版报告卡片

提交 `87e66a7` 把最终报告改成共享的报告卡片。v7 的媒体适配层直接引用 `frontend/src`，重跑会拍到新界面，所以 v8 以 v7 为基础，只重拍露出报告的片段。镜头顺序、时长、配乐和其余屏幕文案都与 v7 相同。本次先交付预览，用户确认后才制作完整视频，记录见 [授权记录](approval.json)。

## 修改

| 位置 | v7 | v8 |
|---|---|---|
| 13–16 秒报告镜头 | 旧版报告消息，完成时显示绿色边框 | 新版报告卡片：状态「模拟内容」、元信息、三个编号章节、「下一步」框与底部说明 |
| 报告机位 | 按旧报告测量，放大 1.79 倍 | 按真实卡片重新测量，完整卡片（含底部说明）入镜，输入框在画面外；放大 1.38 倍，文字比 v7 小 |
| 16–19 秒章节卡 | 进出场露出旧报告 | 露出新卡片，遮盖与揭开的时机不变 |
| 19–23.5 秒方法镜头 | 旧报告缩入为缩略图后淡出 | 缩略图同步为新卡片，缩入路径与时机不变 |
| 报告镜头左侧说明 | 比较维度清楚呈现，已确认与待验证各有归属。 | 比较维度清楚呈现，下一步单独列出。 |

## 已知风险核对

| 风险 | 结果 | 处理 |
|---|---|---|
| `React.lazy` 回退态 | 属实。报告机位曾按回退态测量（高 458.5，卡片实际高 524），放大过度并裁掉卡片顶部；冷启动时还可能拍到回退态 | 只改媒体适配层：测量前先渲染报告并等待 `.cw-report-head`，之后任何一帧出现回退态即报错；`frontend/` 未改 |
| 旧报告校验 | 属实。回退态的文本恰好等于 `demoReport`，旧校验在错误状态下反而通过 | 改为逐帧结构校验；17 种错误状态全部被拒绝，屏蔽卡片代码块后渲染直接失败 |
| 输入框遮挡卡片 | 片子固定按 1920×1032 渲染，卡片底部与输入框相距 55 px，输入框在画面外；1440 宽度截图中的遮挡在片中不出现 | 机位公式不变，改为测量真实卡片；逐帧确认卡片、底部说明与输入框的位置 |
| 写作衔接与看板顶栏 | 375–389 帧镜头仍在节点检查器，「正在撰写」在 v7、v8 都不入镜；390 帧起卡片已是完成态；报告窗口尺寸不变，不压看板顶栏 | 新增逐帧校验：顶栏出现时，报告窗口必须已离开 |
| 文案 | 「完整显示源 demoReport」和「已确认与待验证各有归属」不再符合画面 | 时间轴说明改写；左侧第二行按用户确认改为「下一步单独列出。」 |

卡片元信息中的「51 秒」和「Qwen3.5」是原生组件读取的演示时钟与演示配置，不是实际耗时或实际调用；画面同时标有「模拟内容」和「合成演示 · 流程已压缩」，用户确认保留原生界面。演示数据没有来源，卡片显示「暂无来源」，片中没有引用角标、折叠或来源列表。

## 改动范围

与 v7 的渲染帧逐帧比较（任一通道差值超过 8/255 记为变化，排除版本页脚）：有变化的帧为 390–487、563–703，共 239 帧，全部在报告窗口内；其余 1351 帧最大差值 3/255。配乐 `music.wav` 与 v7 逐位相同，编码后的音频流也与 v7 成片相同；综合响度 -16.1 LUFS、响度范围 5.9 LU、真峰值 -1.7 dBTP，与 v7 一致。v7 及更早版本的文件保持原字节。
